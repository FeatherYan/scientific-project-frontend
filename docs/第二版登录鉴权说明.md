# 第二版登录鉴权说明

这一轮的目标是把第一版骨架里的“登录入口”补成一条可运行、可讲解的完整链路，让项目从纯结构骨架进入“有真实前端流程”的阶段。

---

## 1. 这一轮完成了什么

### 1.1 接入了 MSW 登录接口

已经补充了 mock 登录接口和 mock 用户数据：

- `src/mocks/data/users.ts`
- `src/mocks/handlers/auth.ts`
- `src/mocks/handlers/index.ts`
- `src/mocks/browser.ts`

同时生成了：

- `public/mockServiceWorker.js`

现在开发环境下，登录请求会由 MSW 在浏览器端拦截，不需要真实后端也能完成登录闭环。

### 1.2 应用启动时自动启用 Mock

在 `src/main.tsx` 中加入了 `enableMocking()`，应用启动时会先注册 MSW，再挂载 React 应用。

这样做的好处是：

- 页面发出的请求会被统一拦截
- 不需要在页面里写任何 mock 逻辑
- 后续继续增加 mock 接口时结构一致

### 1.3 登录页改造成表单提交

登录页已经从“角色快捷按钮登录”升级为：

- 用户名输入框
- 密码输入框
- 登录角色选择
- 提交按钮

同时保留了面试演示友好的体验：

- 默认填充 mock 账号
- 点击角色卡片可快速填充示例账号
- 页面直接展示 mock 账号说明

### 1.4 接入了 React Query 的登录 mutation

新增：

- `src/hooks/useLogin.ts`

登录页不再直接写请求，而是通过：

`page -> hook -> api -> request`

这条链路完成登录。

### 1.5 登录成功后写入 Redux 登录态

登录成功后，页面会把返回的认证信息分发到 `authSlice`：

- token
- role
- userInfo
- permissions
- isAuthenticated

并通过本地存储持久化下来。

### 1.6 完善了登录后的跳转逻辑

已经支持两类跳转：

- 正常登录后，根据角色跳转默认首页
- 如果用户原本访问受保护页面，被守卫重定向到登录页，登录成功后会回跳原页面

这也是中后台项目里非常典型的登录体验。

### 1.7 完善了请求错误提示

请求层现在会优先读取后端返回的 `message`，例如登录失败时能直接提示：

> 用户名、密码或角色不匹配

而不是只显示一个泛化的网络报错。

## 2. 这一轮的核心链路

你要把这条链路记熟，它很适合在面试里讲。

```txt
登录页提交表单
  -> useLogin mutation
  -> auth api
  -> axios request 实例
  -> MSW mock 接口返回登录结果
  -> Redux 写入登录态
  -> localStorage 持久化
  -> 路由守卫放行
  -> 按角色跳转到对应页面
```

## 4. 这一轮为什么这样拆

### 4.1 为什么登录页不直接请求接口

答法：

> 因为页面层应该只做页面组合和少量页面逻辑，不应该直接耦合底层请求细节。所以我把登录请求拆成 api 层和 hooks 层，页面只负责收集表单值、触发 mutation 和处理登录成功后的页面行为。

### 4.2 为什么登录成功后还要写 Redux

答法：

> 因为登录态是全局状态，需要被路由守卫、动态菜单、顶部用户信息这些多个地方共同消费，所以应该统一存放在 Redux 里，而不是只留在登录页局部状态里。

### 4.3 为什么还要持久化到 localStorage

答法：

> 因为如果只放在内存里，刷新页面就会丢失登录态。中后台项目里登录态通常需要具备刷新恢复能力，所以我做了本地持久化。

### 4.4 为什么用 MSW 而不是在页面里写假数据

答法：

> 因为 MSW 更接近真实接口调用方式。页面仍然发真实 HTTP 请求，只是请求在浏览器端被 mock 拦截了。这样可以让 request、api、hooks、页面这条链路保持真实，后续切换成后端接口时几乎不用改页面逻辑。

## 5. 你面试里要能讲清楚的点

### 必讲

- 登录页现在已经不是演示按钮，而是完整表单提交
- 登录链路经过 React Query、api 层、axios request、MSW
- 登录成功后写 Redux，再由路由守卫和菜单系统消费
- 登录失败由统一拦截器展示接口返回的错误信息
- 支持“访问受保护页面 -> 跳登录 -> 登录成功回跳原页面”

### 加分点

- MSW 让前端在没有真实后端时也能按真实接口方式开发
- 这套结构后续可以无缝扩展到项目列表、审批列表、通知列表
- 登录页当前保留了示例账号快速填充，适合演示和测试
