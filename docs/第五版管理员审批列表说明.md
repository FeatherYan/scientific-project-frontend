# 第五版管理员审批列表说明

这一轮的目标是把管理员端正式接进来，让用户侧已经提交出来的数据进入审批视角。

---

## 1. 这一轮完成了什么

### 1.1 实现了管理员端审批列表页第一版

页面文件：

- `src/pages/approval/list.tsx`

当前已经具备：

- 审批列表页头部说明
- 关键词搜索
- 审批状态筛选
- 审批表格
- 状态标签展示
- 进入审批详情页入口

### 1.2 接入了审批列表接口

更新了：

- `src/api/approval.ts`
- `src/hooks/useApprovals.ts`
- `src/mocks/handlers/project.ts`

管理员端现在可以通过 `/api/approvals` 获取审批数据。

### 1.3 管理员端看到的数据范围已经做了语义区分

这一版里，审批列表默认不包含草稿数据。

也就是说，管理员只看这些已经进入审批体系的记录：

- 已提交
- 审批中
- 已通过
- 已退回

这样做的目的是让管理员视角和普通用户视角职责更清晰。

---

## 2. 为什么管理员列表不看草稿

这是这一轮最值得讲清楚的业务边界。

可以这样说：

> 草稿阶段还属于用户个人编辑过程，并没有正式进入审批流，所以管理员列表不应该展示草稿。管理员端应该只承接已经提交或已经发生审批流转的数据。

这个处理有两个好处：

- 业务语义更清楚
- 管理员列表更聚焦真正需要审批的记录

## 4. 这一轮的技术链路

```txt
审批列表页筛选条件变化
  -> useApprovalList(params)
  -> api/approval.ts
  -> axios request
  -> MSW mock /api/approvals
  -> React Query 返回数据
  -> 列表渲染
```

这条链路和前面用户端列表页保持一致，所以整个项目的异步数据组织方式是统一的。

## 6. 面试时可以怎么讲这一轮

### 一分钟版本

> 第五轮我开始实现管理员端审批模块，先完成了审批列表页第一版。这个页面承接用户已提交的数据，管理员可以按关键词和状态筛选项目，并进入审批详情页。数据层继续沿用 React Query + axios + MSW 的组织方式，同时我在 mock 接口里明确把草稿排除在管理员视角之外，让审批列表只展示真正进入审批体系的记录。

### 两分钟版本

> 这一轮的重点是把用户侧和管理员侧真正连接起来。我先做的是审批列表页，因为它是管理员处理业务的入口。页面支持按项目名称、编号和申请人搜索，也支持按审批状态筛选。表格中展示申请人、院系、项目类别、经费和状态等核心字段，方便管理员快速判断。架构上我没有把审批逻辑直接塞进项目模块，而是补了独立的 `api/approval` 和 `useApprovals`，这样普通用户端和管理员端的数据访问职责更清楚。业务上我也做了一个关键限制：管理员列表不显示草稿，因为草稿还没有正式进入审批流，只展示已提交、审批中、已通过和已退回的数据。
