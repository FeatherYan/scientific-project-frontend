# 科研项目管理平台 MVP：面试速记版

## 1. 一句话介绍项目

这是一个科研项目管理平台的前端 MVP，模拟高校教师或研究生发起科研项目申报、管理员审批的中后台场景。我重点实现了登录鉴权、角色权限、动态菜单、列表页、复杂表单、审批流、通知联动，以及基于 MSW 的 Mock 接口体系。

## 2. 技术栈

- React + TypeScript + Vite
- Ant Design
- React Router
- Redux Toolkit
- React Query
- axios
- MSW
- dayjs

## 3. 我为什么这么拆

```txt
pages -> hooks -> api -> request -> msw / backend
```

- `request`：axios 实例、拦截器、统一响应处理
- `api`：按模块拆分接口函数
- `hooks`：基于 React Query 封装查询和 mutation
- `store`：只管登录态、用户信息、角色、权限
- `permission`：路由守卫、菜单权限、按钮权限
- `pages`：只做页面组合和少量页面逻辑

## 4. 状态怎么分

- Redux Toolkit：token、用户信息、角色、权限、是否登录
- React Query：项目列表、项目详情、审批列表、审批详情、通知列表
- 页面本地 state：搜索条件、分页、弹窗开关、表单输入态

一句话回答：

> 身份类全局状态放 Redux Toolkit，服务端数据放 React Query，页面交互态放本地 state。

## 5. 权限怎么做

采用简化版 RBAC：

- `user`
- `admin`

权限控制分三层：

- 路由权限
- 菜单权限
- 按钮权限

再叠加业务状态控制：

- 草稿才能提交、删除
- 草稿和已退回才能编辑
- 已提交、审批中、已通过只能查看
- 管理员只在可审批状态下能审批

一句话回答：

> 操作是否可用，通常由角色权限和业务状态共同决定。

## 6. 登录鉴权怎么讲

流程：

1. 登录页提交账号、密码、角色
2. 调用登录接口
3. 保存 token、角色、用户信息
4. 根据角色生成权限列表
5. 跳转默认首页

关键代码：

- `src/pages/login/index.tsx`
- `src/hooks/useLogin.ts`
- `src/store/slices/authSlice.ts`
- `src/permission/routeGuard.tsx`

## 7. 业务闭环怎么讲

普通用户：

1. 查看可申报项目
2. 查看项目详情
3. 发起申报生成草稿
4. 保存草稿或提交
5. 在“我的申报”查看状态
6. 在通知中心接收审批结果

管理员：

1. 查看审批列表
2. 查看审批详情
3. 审批通过或退回
4. 系统联动更新状态和生成通知

## 8. 最容易被问的点

### 为什么不用 Redux 管所有数据

> 因为项目、审批、通知这些都属于服务端状态，React Query 更适合处理缓存、失效刷新和 mutation 后同步。Redux 只保留全局身份信息。

### 为什么菜单是动态的

> 菜单不是单独写死的，而是根据角色和权限从统一配置里过滤出来的，这样路由、菜单、按钮权限共用一套体系。

### 为什么表单页不拆成查看页和编辑页

> 为了降低重复代码，用一个表单页同时承载查看和编辑，再由业务状态决定是否只读，更适合中后台项目。

### 为什么使用 MSW

> 因为这是前端面试项目，没有真实后端，但我希望保留完整请求链路。MSW 可以模拟真实接口，让 request、api、hooks、pages 这条链完整跑通。

### 为什么又加了 localStorage

> 这是演示期替代方案，用来持久化 mock 数据，避免刷新后状态丢失。真实项目里这部分应该由后端数据库负责。
